# INCOLLA IN CLAUDE CODE · FOLYNTRA AI

Agisci come un **team senior** (CTO, product designer, full-stack engineer, ingegnere di automazioni editoriali, QA, data analyst per self-publishing) e **implementa davvero** una web app HTML5/PWA chiamata **FOLYNTRA AI — Publishing Intelligence**. Il codice deve funzionare, non limitarti a mockup o liste di idee. Lavora nel nuovo repository del progetto; non toccare altri progetti esistenti. Lingua UI: **italiano**, supporto libri per mercati Italia/USA/UK/Germania/Francia/Spagna.

**Visone:** un'unica piattaforma che unisce funzionalità equivalenti, ma con implementazione e design originali, a RoboProfit (nicchie), RoboBook (scrittura), RoboAds (pubblicità), aggiungendo editor professionale, design copertine, PDF/EPUB/DOCX, pacchetto KDP, bonus editoriali, A+ content e contabilità royalties. Non copiare codice, logo, design protetti, banche dati proprietarie o parole dei concorrenti.

**IMPORTANTE: leggi tutti i documenti di questo repository** prima di progettare il codice. Le specifiche vincolanti sono `docs/02-SPECIFICA-FUNZIONALE.md`, `docs/03-MOTORE-NICCHIE.md`, `docs/04-ARCHITETTURA.md`, `docs/05-REGOLE-KDP-FONTI.md`, `docs/06-TEST-ACCETTAZIONE.md`, `docs/07-STILE-UX.md` e `CLAUDE.md`. Le utility fornite in `src/lib` sono una base testata, non un'app completa. Prima controlla cosa esiste e non cancellare funzioni già funzionanti.

## Requisiti funzionali: flusso senza salti

1. **Dashboard** con progetti, libri, nicchie, stato dell'editing, esportazioni, spesa AI/Ads, margini netti, progresso e attività recenti.
2. **NICHE INTELLIGENCE** obbligatorio come punto di partenza: scelta mercato/lingua/categoria, brainstorming nicchie e micro-nicchie, query/keyword, domanda, saturazione, competitor, prezzo, reviews, BSR storico se disponibile, tendenze, differenziazione, score spiegabile (0–100), qualità/recenza delle fonti, confidenza, note di rischio, scenari economici, confronto affiancato, salvataggio della nicchia migliore. Aggiungi importazione CSV con validazione e provider adapter **Keepa opzionale**; Google Trends API solo se autorizzata (è alpha), in alternativa import manuale. Nessun dato demo dev'essere presentato come misura reale. **La nicchia selezionata popola automaticamente il brief editoriale**.
3. **BOOK ARCHITECT**: pubblico, problema, proposta unica, titolo + 5 alternative, sottotitolo, sinossi, prefazione, indice gerarchico, numero capitoli, parole obiettivo, stile, lingua, autore, glossario, fonti verificate, callout/box, tabelle, ricette, esercizi, conclusione, ringraziamenti, biografia, bibliografia pertinente. Permetti modifica e blocco capitoli.
4. **BOOK WRITER**: generazione sequenziale capitolo per capitolo con AI Anthropic, salvataggio progressivo e ripresa, versione e timeline, progressi reali, costi/token, budget massimo, revisione stilistica, grammaticale, strutturale e fattuale; evidenzia fonti mancanti e duplicazioni, non inventare referenze o certificazioni di originalità. Per ricettari, template ricetta e controllo coerenza ingredienti; per workbook, schede esercizi. In futuro abilita fiction e illustrated books, senza promettere immagini se provider assente.
5. **COVER & INTERIOR STUDIO**: crea cover originale professionale con template SVG/Canvas/Sharp, modificabile (testi, tipografia, palette, immagini originali o licenziate), 3 proposte differenziate; preview fronte-retro-dorso dimensionata secondo parametri KDP e numero effettivo pagine; eBook cover separata. Impaginazione con scelte formato/carta/bleed, intestazioni, pagine pari-dispari, numerazione, indice paginato PDF, capitoli, riquadri, footer, immagini alta risoluzione. PDF cartaceo, EPUB reflowable, DOCX editabile e anteprima.
6. **KDP PUBLISH KIT**: un click esporta ZIP con manoscritto PDF print, EPUB, DOCX, PDF intera copertina, cover JPG, metadati (titolo, sottotitolo, autore, 7 idee parole chiave, fino a 3 categorie pertinenti), descrizione HTML compatibile, intervalli prezzi/royalty simulati, dichiarazione IA, diritti, checklist per account KDP, guida caricamento manuale e report QA. Blocca 'KDP pronto' se mancano controlli critici. Non affermare di pubblicare direttamente su KDP: **non esiste API pubblica standard**.
7. **BONUS + MARKETING**: genera contenuti bonus realmente coerenti col libro (workbook, checklist, esercizi, schede) in PDF scaricabili, pagina autore, descrizioni, A+ content assets, video script, email di lancio, post social. Evita moduli raccolta email a cui rimanda il Kindle, giveaway vietati e URL non consentiti. Bonus in-book subordinato a linee guida KDP e limite raccomandato 10%.
8. **ADS & ROYALTIES**: Amazon Sponsored Products planner: gruppi keyword, match type, negative, target ASIN solo quando reperiti lecitamente, bids/budget, campagna manuale, import CSV report e calcolo ACOS, ROAS, margine e break-even. Collegamento **API Amazon Ads soltanto dopo reale approvazione e consenso OAuth**. Import royalties KDP tramite CSV fornito dall'utente; analisi per libro/mercato. Nessuna metrica inventata né budget Ads speso senza consenso.

## Stack e implementazione

- Next.js stabile (App Router), React + TypeScript, Tailwind CSS + shadcn/ui + Lucide, responsive e PWA; **design originale premium** dark navy / avorio / oro sobrio e micro-animazioni utili.
- Supabase PostgreSQL/Auth/Storage; applica le RLS di `supabase-schema.sql` e proteggi dati personali/progetti. Nessuna chiave API nel browser. `.env.example` ma mai `.env` con credenziali nel git.
- AI Anthropic via server con model ID da env; provider interface e mock **dichiarato** per UI/test. Richieste streaming e jobs persistenti con retry/idempotenza, limiti costo, timeout, resume per capitolo. Non iniziare generazione di 100k parole in una singola richiesta.
- Export PDF con renderer HTML/CSS paginato su worker compatibile Chromium; EPUB e DOCX validati; immagini cover originali con Sharp/SVG, motore asset plug-in per immagine AI solo se presente API autorizzata; ZIP con manifest + SHA-256. Testa il PDF con strumenti eBook/print quando disponibili; fallback deve dichiarare test non eseguiti.
- Netlify per sito, Supabase per database, workers esterni per rendering/esportazioni pesanti se Netlify non regge; niente deployment dichiarato 'completato' finché URL e flussi non sono verificati.
- Inserisci osservabilità, log errori non sensibili, stato jobs e cost ledger, limiti per utente, validazione input, paginazione, salvataggio automatico.

## ORDINE DI REALIZZAZIONE OBBLIGATORIO

**FASE A — MVP funzionante prima di qualsiasi optional:** autenticazione, dashboard, ricerca nicchie con CSV/import e DEMO chiaramente segnalata, scelta nicchia, brief -> indice -> generazione capitoli AI (quando chiave presente), editing, design cover a template, PDF interior, EPUB, DOCX, export ZIP KDP e checklist. Stato reale: vietati finti pulsanti, finte performance, finte integrazioni.

**FASE B — intelligence e marketing:** Keepa (solo se credenziali), plugin provider trends, confronto nicchie, sales reports, simulatori royalties, Ads planner, contenuti A+, bonus e QA avanzato. **FASE C**: pubblicità API previa approvazione, e-commerce SaaS, team/abbonamenti, traduzioni e illustrazioni dove provider disponibile.

Semplifica senza rompere end-to-end: preferisco **una funzione completa** a 10 pulsanti scenografici che non fanno nulla. Tieni il codice modulare e i costi AI al minimo. Se mancano segreti, implementa la funzionalità con UI setup e mock esplicito, non bloccare tutto il progetto e non dichiarare che l'AI è connessa. Non spendere soldi né attivare API a pagamento senza consenso.
